# Playbook: SaaS / product demo and screen recordings

## Decide the source of the screens
- **Real capture ≥2K (Screen Studio style)** → zoom 1.25–2× following the cursor, smooth cursor,
  motion blur, speed-ramp through loading. Record at app zoom 110–125%.
- **1080p capture inside a vertical reel (webinars, Zoom)** → NOT legible. Rebuild the UI as
  full-screen components that match the real product (layout, labels, colours) and navigate like a
  user: tab switch → click → menu → load → scroll. Cursor clicks land on the spoken word.
- Real numbers when available (read at the moment they're spoken); illustrative numbers only with
  approval, labelled as examples in captions/notes.

## Building rebuilt UI fast
- Study the product first: frontend source if available, store listing screenshots, website.
- One component per screen, props = data; the frame IS the app (full-bleed), with a light filmed
  layer (slow push/drift, warm tint, grain, vignette).
- Show one idea per screen; highlight the element being talked about (ring/row tint), not with
  arrows and stickers.
- Keep the speaker present: lip-synced cam in a bottom panel or corner while they talk.

## Beat sheet (30–45 s)
Hook (the pain, spoken, frame 0) → old way (visible failure: filters piling up, error state) →
switch to the product → 2–3 clicks that show the result → the payoff number/screen → CTA.
